# Скилл: страница-визитка специалиста за пять минут

## Задача

Собрать публичную страницу мастера, врача, психолога или небольшого заведения: имя,
специальность, контакты, прайс, ссылки на соцсети. Страница открывается по адресу
`https://app.qrtap.kg/a/<slug>` и работает на телефоне. К ней сразу делается QR-код для
визитки или витрины.

## Когда применять

- У специалиста нет сайта, а ссылку на себя давать нужно.
- Нужна визитка с QR: отсканировал — сразу телефон, WhatsApp и прайс.
- Прайс меняется, и переделывать сайт ради двух строк никто не станет.

## Что понадобится

- `QRTAP_API_KEY` ([где взять](https://app.qrtap.kg/workspace/api)).
- Минимум: имя и **хотя бы один контакт** — телефон, WhatsApp, Instagram или ссылка на
  запись. Без контакта запись отклоняется с ошибкой 422 `invalid_content`.

## Шаги

### 1. Собрать содержимое

Все поля необязательны, кроме `name`. Полный набор:

| Поле | Что это |
|---|---|
| `name` | Заголовок страницы, до 80 символов — обязательное |
| `segment` | Тип страницы: `master`, `vrach`, `psiholog`, `otzyvy`. По умолчанию `master` |
| `theme` | Цвет: `emerald`, `ocean`, `plum`, `terracotta`, `graphite` |
| `specialty` | Подзаголовок, до 120 символов |
| `bio` | Описание, до 1200 символов |
| `phone` | Телефон в любом виде, сохраняется как `+цифры` |
| `whatsapp` | Номер, сохраняется ссылкой `wa.me` |
| `instagram` | `@ник` или ссылка на профиль |
| `twogis` | Ссылка на карточку 2ГИС |
| `bookingUrl` | Внешняя ссылка на запись |
| `hours` | Часы работы одной строкой, до 160 символов |
| `address` | Адрес одной строкой, до 200 символов |
| `licenseNumber` | Номер лицензии — для регулируемых профессий |
| `services` | До 12 услуг: `[{"name": "...", "price": "..."}]`, цена свободным текстом |
| `reviewLinks` | Ссылки на отзывы: `twogis`, `google`, `yandex`, `flamp` |
| `socialLinks` | Иконки: `tiktok`, `telegram`, `website`, `youtube` |

Всё содержимое чистится на сервере: неизвестные поля отбрасываются, телефоны нормализуются,
из ссылок выживают только `http` и `https`. Придумывать поля бесполезно — они просто не
сохранятся.

### 2. Опубликовать страницу

**Через MCP:**

```
qrtap_create_page(content = {
  "name": "Айгуль Осмонова",
  "segment": "master",
  "theme": "plum",
  "specialty": "Мастер маникюра",
  "phone": "0555 123 456",
  "whatsapp": "0555 123 456",
  "instagram": "@aigul.nails",
  "address": "Бишкек, Киевская 95",
  "hours": "Вт–Сб, 10:00–19:00",
  "services": [
    {"name": "Маникюр с покрытием", "price": "1500 сом"},
    {"name": "Педикюр", "price": "2000 сом"}
  ]
})
```

**Через HTTP:**

```bash
curl -s -X POST https://app.qrtap.kg/api/v1/pages \
  -H "Authorization: Bearer $QRTAP_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"content": {
    "name": "Айгуль Осмонова",
    "segment": "master",
    "theme": "plum",
    "specialty": "Мастер маникюра",
    "phone": "0555 123 456",
    "whatsapp": "0555 123 456",
    "services": [{"name": "Маникюр с покрытием", "price": "1500 сом"}]
  }}'
```

В ответе — `slug` и `public_url`. Вызов безопасно повторять: он обновляет ту же страницу
новой версией, а не создаёт вторую, и `slug` не меняется.

### 3. Сделать QR на страницу

```
qrtap_create_code(url = "<public_url из ответа>", title = "Визитка Айгуль", external_ref = "vizitka-aigul")
```

Дальше `png_url` из ответа идёт в макет визитки, а PDF для типографии забирается так:

```bash
curl -H "Authorization: Bearer $QRTAP_API_KEY" \
  "https://app.qrtap.kg/api/v1/codes/$CODE_ID/qr?format=pdf" -o vizitka-qr.pdf
```

### 4. Менять содержимое потом

Здесь легко потерять данные. `PATCH` заменяет содержимое **целиком**: любое непереданное
поле стирается. Порядок такой:

```bash
# 1. Прочитать текущее содержимое
curl -s -H "Authorization: Bearer $QRTAP_API_KEY" \
  "https://app.qrtap.kg/api/v1/pages/$SLUG"

# 2. Изменить нужное поле в полученном объекте content

# 3. Отправить объект целиком
curl -s -X PATCH "https://app.qrtap.kg/api/v1/pages/$SLUG" \
  -H "Authorization: Bearer $QRTAP_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"content": { ...весь объект с правкой... }}'
```

Через MCP это `qrtap_get_page(slug)` → правка → `qrtap_update_page(slug, content)`.
`qrtap_list_pages` для чтения не годится: он специально не отдаёт `content`.

`slug` и `public_url` при обновлении не меняются, напечатанные визитки продолжают работать.

## Как проверить результат

1. **Страница создана.** В ответе есть `slug`, `public_url`, `published: true`.
2. **Открывается.** `curl -sI <public_url>` возвращает `200`.
3. **Содержимое на месте.** `GET /api/v1/pages/{slug}` показывает то, что отправляли, с
   нормализованными телефоном и ссылками (`whatsapp` стал `https://wa.me/...`).
4. **Версия растёт.** После каждого обновления `version` увеличивается на единицу.
5. **QR ведёт куда надо.** `curl -sI <short_url>` показывает в `location` адрес страницы.

## Типичные ошибки

| Симптом | Причина | Что делать |
|---|---|---|
| `422 invalid_content` | Нет ни одного контакта | Добавить `phone`, `whatsapp`, `instagram` или `bookingUrl` |
| После правки пропали услуги | `PATCH` отправлен с частичным `content` | Читать страницу перед записью и отправлять объект целиком |
| Не сохранилось выдуманное поле | Неизвестные ключи отбрасываются | Пользоваться только полями из таблицы выше |
| Создалась «вторая страница» | В рабочем пространстве страница одна | Повторный `POST` обновляет ту же страницу — это ожидаемо |
| Ссылка на соцсеть исчезла | Был не `http`/`https` адрес | Указывать полный адрес со схемой |
