# Скилл: один QR — отзывы на 2ГИС, Google и Яндекс

## Задача

Один код на столе, у кассы или на визитке, по которому гость сам выбирает площадку и
оставляет отзыв. Вместо трёх наклеек — одна, и не нужно угадывать, где именно клиент
привык писать.

## Когда применять

- Заведение собирает отзывы, но не хочет клеить по коду на каждую площадку.
- Нужно поднять карточку в 2ГИС и в Google одновременно.
- Отзывы просят «в моменте» — пока гость ещё здесь.

## Как это устроено

Публичная страница с типом `segment: "otzyvy"` показывает кнопки площадок из поля
`reviewLinks`. QR ведёт на эту страницу, гость выбирает площадку и уходит писать отзыв туда.
Набор площадок меняется в любой момент — код остаётся тем же.

Отдельно от этого на странице работает своя форма отзыва: то, что гость пишет прямо на
странице, попадает в очередь модерации и не публикуется, пока владелец не разрешит.

## Что понадобится

- `QRTAP_API_KEY` ([где взять](https://app.qrtap.kg/workspace/api)).
- Прямые ссылки на карточки заведения. Их берут в самих сервисах:
  - **2ГИС** — карточка компании, вкладка отзывов;
  - **Google** — «Поделиться» → ссылка на отзыв в профиле компании;
  - **Яндекс** — карточка в Яндекс Картах, раздел отзывов;
  - **Flamp** — если карточка есть.

Ссылки должны быть рабочие и со схемой `https`. Проверьте каждую вручную перед записью:
битая ссылка здесь означает потерянный отзыв.

## Шаги

### 1. Создать страницу-воронку

Поле `reviewLinks` принимает четыре ключа: `twogis`, `google`, `yandex`, `flamp`. Достаточно
одного, лишние можно не указывать.

**Через MCP:**

```
qrtap_create_page(content = {
  "name": "Кофейня «Тандем»",
  "segment": "otzyvy",
  "theme": "terracotta",
  "specialty": "Спасибо, что зашли — расскажите, как всё прошло",
  "phone": "0555 123 456",
  "reviewLinks": {
    "twogis": "https://2gis.kg/bishkek/firm/70000001234567890",
    "google": "https://g.page/r/CXXXXXXXXXXXXXXX/review",
    "yandex": "https://yandex.ru/maps/org/tandem/1234567890/reviews/"
  }
})
```

**Через HTTP:**

```bash
curl -s -X POST https://app.qrtap.kg/api/v1/pages \
  -H "Authorization: Bearer $QRTAP_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"content": {
    "name": "Кофейня «Тандем»",
    "segment": "otzyvy",
    "theme": "terracotta",
    "phone": "0555 123 456",
    "reviewLinks": {
      "twogis": "https://2gis.kg/bishkek/firm/70000001234567890",
      "google": "https://g.page/r/CXXXXXXXXXXXXXXX/review",
      "yandex": "https://yandex.ru/maps/org/tandem/1234567890/reviews/"
    }
  }}'
```

Помните про обязательный контакт: `name` плюс хотя бы одно из `phone`, `whatsapp`,
`instagram`, `bookingUrl`. Иначе `422 invalid_content`.

### 2. Сделать QR

```
qrtap_create_code(
  url = "<public_url из ответа>",
  title = "Отзывы, стол и касса",
  external_ref = "otzyvy-glavnaya"
)
```

Для печати на наклейке:

```bash
curl -H "Authorization: Bearer $QRTAP_API_KEY" \
  "https://app.qrtap.kg/api/v1/codes/$CODE_ID/qr?format=svg&caption=Отзывы" -o otzyvy.svg
```

Подпись проверяется на промо-формулировки: «отзыв за скидку» и подобное отклоняется с
ошибкой 422. Просить отзыв за вознаграждение — отдельный риск и по закону о рекламе, и по
правилам самих площадок; лучше не надо.

### 3. Добавить или заменить площадку потом

Тот же порядок «прочитать — поправить — записать целиком»:

```bash
# прочитать
curl -s -H "Authorization: Bearer $QRTAP_API_KEY" "https://app.qrtap.kg/api/v1/pages/$SLUG"
# записать объект content целиком, добавив в reviewLinks нужный ключ
curl -s -X PATCH "https://app.qrtap.kg/api/v1/pages/$SLUG" \
  -H "Authorization: Bearer $QRTAP_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"content": { ...весь объект... }}'
```

Через MCP: `qrtap_get_page` → правка → `qrtap_update_page`.

### 4. Разбирать отзывы, оставленные на самой странице

Очередь модерации — статус `pending`. Ничего из неё не видно публично, пока не опубликуют.

```bash
curl -s -H "Authorization: Bearer $QRTAP_API_KEY" \
  "https://app.qrtap.kg/api/v1/reviews?status=pending"
```

В ответе: `id`, `author_name` (как гость подписался), `body` (до 600 символов), `status`,
`created_at`. Ничего больше — ни IP, ни устройства.

Решение по отзыву:

```bash
curl -s -X POST "https://app.qrtap.kg/api/v1/reviews/$REVIEW_ID/moderate" \
  -H "Authorization: Bearer $QRTAP_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"action": "publish"}'   # или "hide"
```

Через MCP: `qrtap_list_reviews(status = "pending")` → `qrtap_moderate_review(reviewId, action)`.

**Это публичное действие.** Опубликованный отзыв сразу виден всем. Ассистент показывает
пользователю текст отзыва и подпись, называет действие и ждёт согласия. Решать за владельца,
что публиковать, а что скрыть, — не дело ассистента: скрытие негативного отзыва это его
выбор и его репутационный риск.

## Как проверить результат

1. **Страница живая.** `curl -sI <public_url>` возвращает `200`.
2. **Кнопки на месте.** `GET /api/v1/pages/{slug}` показывает `reviewLinks` с вашими адресами;
   `segment` равен `otzyvy`.
3. **Ссылки рабочие.** Каждую из `reviewLinks` открыть руками и убедиться, что попадаете на
   форму отзыва, а не на общую карточку.
4. **QR ведёт на страницу.** `curl -sI <short_url>` → в `location` адрес страницы.
5. **Сканы считаются.** `GET /api/v1/codes/{id}/stats` — сколько раз просили отзыв.
6. **Очередь работает.** Оставить тестовый отзыв через страницу и найти его в
   `?status=pending`.

## Типичные ошибки

| Симптом | Причина | Что делать |
|---|---|---|
| Кнопок площадок нет | `segment` не `otzyvy` либо `reviewLinks` пустой | Проверить оба поля через `GET /api/v1/pages/{slug}` |
| Ссылка ведёт на карточку, а не на форму отзыва | Взят обычный адрес компании | Взять именно ссылку на добавление отзыва |
| Пропали площадки после правки | `PATCH` с частичным `content` | Читать перед записью, отправлять объект целиком |
| Отзыва не видно на странице | Он в очереди `pending` | Опубликовать через `moderate` — с согласия владельца |
| `422` на подписи к QR | Промо-формулировка в `caption` | Оставить нейтральное «Отзывы» |
