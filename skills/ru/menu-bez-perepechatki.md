# Скилл: меню или прайс, который можно менять без перепечатки

## Задача

Сделать QR-код для меню, прайса или афиши так, чтобы напечатать его один раз, а содержимое
менять сколько угодно. Код на столе, в витрине или на стене остаётся прежним — меняется
только адрес, куда он ведёт.

## Когда применять

- Кафе меняет меню по сезонам, а таблички на столах перепечатывать не хочет.
- Мастерская или салон обновляет прайс раз в квартал.
- Афиша на витрине должна вести на актуальное мероприятие.
- Любой случай, когда «напечатали, а через месяц всё поменялось».

Не подходит, если ссылка нужна разовая и печатать её не будут — тогда достаточно обычной
короткой ссылки.

## Что понадобится

- `QRTAP_API_KEY` — ключ рабочего пространства ([где взять](https://app.qrtap.kg/workspace/api)).
- Адрес, куда код ведёт сейчас: PDF меню в облаке, страница сайта, папка с прайсом. Годится
  любой `http`/`https`.

## Шаги

### 1. Создать код

Один вызов. В ответе важны три поля: `id` (по нему потом менять адрес), `short_url`
(постоянная ссылка, которую кодирует QR) и `png_url` (картинка для макета).

**Через MCP:**

```
qrtap_create_code(
  url = "https://example.com/menu-summer.pdf",
  title = "Меню на столах, зал",
  external_ref = "menu-hall",
  group = "event_menu"
)
```

**Через HTTP:**

```bash
curl -s -X POST https://app.qrtap.kg/api/v1/codes \
  -H "Authorization: Bearer $QRTAP_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "target_url": "https://example.com/menu-summer.pdf",
    "label": "Меню на столах, зал",
    "external_ref": "menu-hall",
    "group": "event_menu"
  }'
```

`external_ref` — собственное имя кода. Оно делает создание идемпотентным: повторный вызов с
тем же `external_ref` вернёт уже существующий код, а не создаст второй. Ставьте его всегда.

### 2. Забрать файл для печати

`png_url` и `svg_url` приходят в ответе. Для типографии удобнее PDF — он векторный:

```bash
CODE_ID=<id из ответа>
curl -H "Authorization: Bearer $QRTAP_API_KEY" \
  "https://app.qrtap.kg/api/v1/codes/$CODE_ID/qr?format=pdf" -o menu-qr.pdf
```

Форматы: `png` (растр, `size` от 256 до 3000 — для печати берите ~2000), `svg` (вектор,
поддерживает подпись через `caption`), `pdf` (одна страница, для типографии).

Подпись `caption` проверяется на соответствие закону КР о рекламе: слова про скидки, бонусы,
подарки и промокоды отклоняются с ошибкой 422. Для подписи под кодом используйте нейтральное
«Меню», «Прайс», «Афиша».

### 3. Напечатать и разместить

Печатается `short_url`, зашитый в QR. Он не изменится никогда — ни при смене меню, ни при
смене тарифа. Это и есть смысл всей затеи.

### 4. Поменять содержимое, когда придёт время

Печать не трогаем — меняем адрес:

**Через MCP:**

```
qrtap_change_destination(codeId = "<id>", url = "https://example.com/menu-autumn.pdf")
```

**Через HTTP:**

```bash
curl -s -X PATCH "https://app.qrtap.kg/api/v1/codes/$CODE_ID" \
  -H "Authorization: Bearer $QRTAP_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"target_url": "https://example.com/menu-autumn.pdf"}'
```

Новый адрес работает со следующего скана, без задержки. Старый сохраняется в истории.

Это публичное действие: со следующей секунды гости увидят другое меню. Ассистент показывает
пользователю старый и новый адрес и ждёт подтверждения, прежде чем вызывать.

### 5. Найти код, если `id` потерялся

По собственному имени:

```bash
curl -s -H "Authorization: Bearer $QRTAP_API_KEY" \
  "https://app.qrtap.kg/api/v1/codes?external_ref=menu-hall"
```

Или списком с количеством сканов у каждого:

```bash
curl -s -H "Authorization: Bearer $QRTAP_API_KEY" \
  "https://app.qrtap.kg/api/v1/codes?include=stats"
```

## Как проверить результат

1. **Код создан.** В ответе есть `short_url` вида `https://app.qrtap.kg/xxxx`.
2. **Ссылка живая.** `curl -sI <short_url>` возвращает редирект (301/302) на текущий адрес.
3. **Адрес сменился.** После шага 4 повторный `curl -sI <short_url>` показывает в заголовке
   `location` уже новый адрес, а `short_url` при этом прежний.
4. **История пишется.** `GET /api/v1/codes/{id}/history` показывает обе версии: активную и
   `superseded`. Это же способ вернуть предыдущий адрес, если промахнулись.
5. **Сканы считаются.** `GET /api/v1/codes/{id}/stats` — сумма, разбивка по дням и по
   устройствам. Данные анонимные и агрегированные: IP и user-agent не хранятся, поэтому
   «кто именно сканировал» узнать нельзя ни через API, ни в кабинете.

## Развитие сценария

**Разное меню в разное время.** Smart Links: до пяти правил, первое совпавшее выигрывает,
иначе основной адрес. Утром — завтраки, вечером — основное меню:

```bash
curl -s -X PUT "https://app.qrtap.kg/api/v1/codes/$CODE_ID/smart-rules" \
  -H "Authorization: Bearer $QRTAP_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"rules": [
    {"if": {"kind": "hours", "tz": "Asia/Bishkek", "from": "08:00", "to": "12:00"},
     "to": "https://example.com/breakfast.pdf"}
  ]}'
```

Правила заменяются целиком: сначала прочитайте текущие через `GET .../smart-rules`, потом
отправляйте полный набор. Пустой массив снимает все правила.

**Много кодов сразу** (на каждый стол, на каждый филиал) — см.
[скилл про партию кодов](partiya-kodov.md).

## Типичные ошибки

| Симптом | Причина | Что делать |
|---|---|---|
| `401 unauthorized` | Ключа нет, он неверен или отозван | Проверить `QRTAP_API_KEY`, при необходимости выпустить новый в кабинете |
| `422` при запросе артефакта с подписью | В `caption` попали слова про скидки или подарки | Убрать промо-формулировки, оставить нейтральную подпись |
| `429` | Кончился бюджет: `scope=minute` — минутный, `scope=day` — суточный | Смотреть `scope` и `Retry-After`; суточный восстановится в полночь UTC |
| Создались два кода на одно меню | Не задан `external_ref` | Задавать всегда; повторный вызов тогда возвращает существующий код |
| QR не читается после брендирования | Логотип перекрыл рисунок | Платформа сама уменьшает или снимает логотип; смотрите заголовок `X-QRTap-QA`: `branded`, `downgraded` или `plain` |
