# qrtap-mcp — QRTap для ИИ-ассистентов

MCP-сервер (stdio), через который Claude или любой другой MCP-совместимый ассистент ведёт
рабочее пространство [QRTap](https://app.qrtap.kg): перенастраиваемые QR-коды и короткие
ссылки, публичные страницы, отзывы гостей, заявки на запись и условные редиректы.

**English version: [README.md](./README.md).**

## Зачем это нужно

QR-код QRTap кодирует постоянную короткую ссылку, а адрес назначения за ней остаётся
редактируемым сколько угодно долго. Код печатается на меню, прайсе, витрине или визитке
один раз — дальше меняется только то, куда он ведёт. Ничего не перепечатывается.

Поэтому продукт хорошо ложится на работу агента: «повесь QR на летнее меню», «переведи
наклейку на новый прайс», «выпусти 120 кодов по филиалам, по одному на филиал», «есть новые
заявки?» — всё это один-два вызова инструмента.

## Установка

```bash
npx -y qrtap-mcp        # запустить stdio-сервер
npm i -g qrtap-mcp      # либо поставить бинарь qrtap-mcp
```

Нужен Node 20 или новее и больше ничего: пакет — собранный JavaScript **без зависимостей
времени выполнения**, поэтому `npx` качает около 22 кБ и сервер поднимается сразу, без
докачки тулчейна при первом запуске. Общение по MCP идёт в stdin/stdout, в stderr — логи.

## Настройка

| Переменная | Значение |
|---|---|
| `QRTAP_API_KEY` | **Обязательно.** API-ключ рабочего пространства. |
| `QRTAP_API_URL` | База API. По умолчанию `https://app.qrtap.kg`. |

**Где взять ключ.** Владелец выпускает его в кабинете QRTap:
[app.qrtap.kg/workspace/api](https://app.qrtap.kg/workspace/api). Ключ показывается один
раз, действует в правах всего рабочего пространства и там же отзывается. Ключ выпускается на
**любом тарифе, включая бесплатный** — интеграцию можно попробовать до покупки. Тариф меняет
не доступ, а объём и набор возможностей: см. [Лимиты и тарифы](#лимиты-и-тарифы) ниже и
[app.qrtap.kg/pricing](https://app.qrtap.kg/pricing).

Обращайтесь с ключом как с паролем: место ему в блоке `env` MCP-клиента, а не в промпте,
репозитории или общем документе.

### Claude Desktop

Настройки → Developer → Edit Config, затем в `claude_desktop_config.json`:

```json
{
  "mcpServers": {
    "qrtap": {
      "command": "npx",
      "args": ["-y", "qrtap-mcp"],
      "env": { "QRTAP_API_KEY": "qrtap_key_XXXX" }
    }
  }
}
```

### Claude Code

```bash
claude mcp add qrtap --env QRTAP_API_KEY=qrtap_key_XXXX -- npx -y qrtap-mcp
```

### Cursor, Windsurf, VS Code и другие MCP-клиенты

Тот же блок подходит везде, где принимается стандартная структура `mcpServers` —
`.cursor/mcp.json`, `.mcp.json` в корне проекта или собственный файл настроек клиента.

## Инструменты

Двадцать инструментов поверх публичного REST API v1. Чтение можно вызывать свободно;
четыре помеченных **публичный эффект** меняют то, что видят реальные клиенты, — их описания
требуют от агента сперва согласовать действие с пользователем.

### Коды и короткие ссылки

| Инструмент | Эндпоинт |
|---|---|
| `qrtap_create_code(url, title?, external_ref?, group?, design_template_id?)` | `POST /api/v1/codes` |
| `qrtap_create_codes_bulk(items[])` | `POST /api/v1/codes/bulk` — до 500, результат по каждому |
| `qrtap_list_codes(group?, external_ref?, include_stats?, limit?, offset?)` | `GET /api/v1/codes` |
| `qrtap_get_code(codeId)` | `GET /api/v1/codes/{id}` |
| `qrtap_change_destination(codeId, url)` — **публичный эффект** | `PATCH /api/v1/codes/{id}` |
| `qrtap_code_history(codeId)` | `GET /api/v1/codes/{id}/history` |
| `qrtap_create_short_link(url)` | `POST /api/v1/codes` |
| `qrtap_list_design_templates()` | `GET /api/v1/design-templates` |

### Аналитика

| Инструмент | Эндпоинт |
|---|---|
| `qrtap_code_stats(codeId, from?, to?)` | `GET /api/v1/codes/{id}/stats` |
| `qrtap_group_stats(group, from?, to?)` | `GET /api/v1/groups/{group}/stats` |

Статистика сканов анонимная и агрегированная по устройству продукта: сумма, разбивка по
дням и по типам устройств. Боты исключены, IP и user-agent посетителей не хранятся —
поэтому персональных записей, которые агент мог бы запросить, попросту не существует.

### Публичные страницы (`/a/{slug}`)

| Инструмент | Эндпоинт |
|---|---|
| `qrtap_list_pages()` | `GET /api/v1/pages` |
| `qrtap_get_page(slug)` | `GET /api/v1/pages/{slug}` |
| `qrtap_create_page(content)` | `POST /api/v1/pages` |
| `qrtap_update_page(slug, content)` | `PATCH /api/v1/pages/{slug}` |

### Отзывы и заявки

| Инструмент | Эндпоинт |
|---|---|
| `qrtap_list_reviews(status?)` | `GET /api/v1/reviews` (по умолчанию `pending`) |
| `qrtap_moderate_review(reviewId, action)` — **публичный эффект** | `POST /api/v1/reviews/{id}/moderate` |
| `qrtap_list_bookings(status?)` | `GET /api/v1/bookings` |
| `qrtap_set_booking_status(bookingId, status)` — **публичный эффект** | `POST /api/v1/bookings/{id}/status` |

### Smart Links (условные редиректы)

| Инструмент | Эндпоинт |
|---|---|
| `qrtap_get_smart_rules(codeId)` | `GET /api/v1/codes/{id}/smart-rules` |
| `qrtap_set_smart_rules(codeId, rules)` — **публичный эффект** | `PUT /api/v1/codes/{id}/smart-rules` |

### Два правила, которые агенту стоит знать

**Сначала прочитать, потом перезаписывать.** `qrtap_update_page` и `qrtap_set_smart_rules`
заменяют содержимое целиком — всё, что не передано, стирается. Прочитайте текущее состояние
через `qrtap_get_page` / `qrtap_get_smart_rules`, внесите правку и отправьте объект целиком.

**Партии — всегда с `external_ref`.** Создание идемпотентно по `external_ref`: повторный
вызов вернёт существующий код, а не создаст дубль. Именно это делает безопасным повторный
прогон частично сбойнувшей партии.

## Файлы для печати

`png_url` и `svg_url` приходят с каждым кодом. Для типографии удобнее PDF — эндпоинты
артефактов требуют того же Bearer-ключа:

```bash
curl -H "Authorization: Bearer $QRTAP_API_KEY" \
  "https://app.qrtap.kg/api/v1/codes/$CODE_ID/qr?format=pdf" -o code.pdf
```

`format` — `png` | `svg` | `pdf`; `size` задаёт ширину PNG (256–3000, для печати ~2000).
PNG перед выдачей проверяется обратным декодированием. Отдельным инструментом рендер не
вынесен: на выходе бинарный файл, а не текст, с которым агент может работать.

## Лимиты и тарифы

На каждый вызов `/api/v1` действуют два бюджета сразу: минутный тормоз и суточная квота.
Оба задаются тарифом рабочего пространства.

| Тариф | В минуту | В сутки | Активных ключей | Bulk и scan-вебхуки |
|---|---|---|---|---|
| Бесплатный | 60 | 100 | 1 | нет |
| Стандартный | 120 | 5 000 | 3 | да |
| Полный | 300 | 50 000 | 10 | да |

Бесплатный тариф существует, чтобы разработчик или агент мог попробовать API до покупки:
100 запросов в сутки хватает на интеграцию и демонстрацию и не хватает на эксплуатацию.

При превышении API отвечает `429` и говорит, что именно кончилось:
`{"error":"rate_limited","scope":"minute"}` — ждать секунды,
`{"error":"quota_exceeded","scope":"day"}` — ждать полуночи UTC. В обоих случаях приходят
`Retry-After` и заголовки `X-RateLimit-Limit` / `-Remaining` / `-Reset`; результат
инструмента передаёт всё это дословно, чтобы агент отступил, а не долбился дальше.

Две привычки экономят бюджет на любом тарифе: вместо цикла — `qrtap_create_codes_bulk`,
вместо поштучной статистики — `qrtap_list_codes(include_stats=true)`.

`qrtap_create_codes_bulk` требует платного тарифа. На бесплатном приходит `402
plan_required` с текущим тарифом и ссылкой на переход; запасной путь — цикл из
`qrtap_create_code` в пределах суточной квоты. Актуальные лимиты живут в платформе ровно в
одном месте — `API_PLAN_LIMITS`, — и таблица выше повторяет их.

## Ошибки

Сбои API возвращаются обычным результатом инструмента с `isError: true`, где текстом лежат
HTTP-статус и тело ответа: агент может их прочитать и объяснить, а не упасть. Ошибкой
JSON-RPC (`-32602`) считается только неизвестное имя инструмента.

| Статус | Что значит |
|---|---|
| `401` | Ключа нет, он неверен или отозван |
| `402 plan_required` | Запрос корректен, но тариф не включает возможность (bulk, scan-вебхуки) |
| `404` | Объекта нет **в вашем** рабочем пространстве — чужой ресурс намеренно неотличим от опечатки в id |
| `422` | Содержимое отклонено: страница без контакта или подпись к QR с промо-формулировкой |
| `429` | Бюджет исчерпан; смотрите `scope` и соблюдайте `Retry-After` |

## Разработка

Команды запускаются из каталога пакета — одинаково в монорепозитории и в публичном зеркале:

```bash
npm install          # только в первый раз
npm test             # vitest: маппинг инструмент→HTTP и диспетчеризация MCP
npm run typecheck
```

Ручной прогон — по одному JSON-RPC-сообщению в строке:

```bash
npm run build    # сначала должен появиться dist/
QRTAP_API_KEY=qrtap_key_XXXX node bin/qrtap-mcp.mjs <<'EOF'
{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2025-06-18","capabilities":{},"clientInfo":{"name":"smoke","version":"0"}}}
{"jsonrpc":"2.0","method":"notifications/initialized"}
{"jsonrpc":"2.0","id":2,"method":"tools/list"}
EOF
```

В npm уезжает собранный JavaScript в `dist/`, и у пакета **нет зависимостей времени
выполнения**: `npx -y qrtap-mcp` качает около 22 кБ и запускается на чистом Node, без
предварительной установки тулчейна. `prepack` пересобирает `dist/` при каждом `npm pack` и
`npm publish` — опубликовать несобранное или устаревшее нельзя.

```bash
npm run build     # tsc -p tsconfig.build.json → dist/
```

Исходники на TypeScript лежат в `src/` в репозитории (MIT, см. ниже), но в архив не попадают.
Протокол MCP реализован прямо в `src/server.ts`; во внутренних импортах стоит явное
расширение `.js` — `tsc` не переписывает пути, а собранный ESM должен резолвиться под чистым
Node.

## Про этот репозиторий

Здесь лежит исходник npm-пакета `qrtap-mcp`: сам сервер, его тесты и скиллы для
ассистентов. Остальная платформа QRTap (веб-приложение, API, база) закрыта и живёт в
приватном репозитории, поэтому история тут начинается с первого публичного релиза, а не с
первого коммита.

Одного теста намеренно нет. `plan-limits.test.ts` читает тарифную сетку из пакета базы и
сверяет числа в этом README с тем, что реально продаётся; он работает только там, где есть
обе половины, и поэтому остался в приватном репозитории.

Вопросы и правки по серверу, скиллам и документации принимаются здесь.
